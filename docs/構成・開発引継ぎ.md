# ashiato 構成・開発引継ぎ書

この文書は、後任の開発者が環境構築、既存機能の変更、公開後の運用を続けるための案内です。秘密値はこの文書やGitHubに記録せず、Cloudflare PagesとGASの安全な設定画面で管理してください。

## 1. 全体構成

```text
利用者のブラウザー
  ├─ React / TypeScript / Vite画面
  ├─ IndexedDB: 端末ごとの足跡・スポット
  ├─ Google Drive API: 写真・動画のファイル本体
  └─ HTTPS same-origin API
       └─ Cloudflare Pages Functions
            ├─ /api/auth: メール認証、署名Cookie発行
            ├─ /api/sync: Cookieを検証しGASへ中継
            └─ /api/oauth/*: Capacitor用Google OAuth
                 └─ Google Apps Script (GAS)
                      └─ Googleスプレッドシート
                           ├─ Users: アカウント情報とハッシュ
                           ├─ Points: GPS地点
                           └─ Spots: お気に入りスポットとDrive参照情報

GitHubリポジトリ ──連携・push──> Cloudflare Pages
                                   ├─ npm run build → dist/
                                   └─ functions/ → Pages Functions
```

Cloudflare PagesがWeb画面とAPIを同一オリジンで提供します。ブラウザーからGASを直接呼び出さず、Pages Functionsが秘密のサービスキーとセッションCookieを使って中継します。GASはPagesが発行したHMAC署名付きセッションを検証し、`sub`（アカウントID）を使ってシート内の利用者データを分離します。

## 2. 技術・ディレクトリ

| パス | 役割 |
|---|---|
| `src/App.tsx` | 画面、ログイン／登録、GPS記録、スポット作成、Driveアップロード、同期 |
| `src/App.css`, `src/index.css` | 画面スタイル |
| `src/data.ts` | IndexedDBでの端末内保存と旧形式データ読み込み |
| `src/types.ts` | 足跡・スポット・アプリデータの型 |
| `src/main.tsx` | React起動、ProductionのService Worker登録 |
| `functions/_shared/account-auth.ts` | GAS呼出し、PBKDF2、HMACセッション、Cookie、Origin検証 |
| `functions/api/auth.ts` | `GET/POST /api/auth`。ログイン、登録、ログアウト、ログイン状態確認 |
| `functions/api/sync.ts` | `POST /api/sync`。認証Cookie検証、GASへの同期中継 |
| `functions/api/oauth/start.ts` | Capacitor用Google OAuth開始 |
| `functions/api/oauth/callback.ts` | OAuthコードをアクセストークンに交換し、Capacitorへ戻す |
| `gas/Code.gs` | GAS Webアプリの入口、認証検証、シート入出力、データ検証 |
| `public/manifest.webmanifest`, `public/sw.js`, `public/icons/` | PWA設定、アプリシェルのキャッシュ、アイコン |
| `android/`, `ios/`, `capacitor.config.ts` | Capacitorネイティブプロジェクト |
| `wrangler.toml` | Pagesのビルド出力先（`dist`）と互換日付 |
| `README.md`, `docs/` | プロジェクト概要、利用者向け・開発者向け資料 |

`npm run build` はTypeScriptのProject Build（`tsc -b`）後にViteで`dist/`を生成します。Pages FunctionsはCloudflare Pagesの規約に従い`functions/`から自動認識されます。

### 主なコマンド

| コマンド | 用途 |
|---|---|
| `npm install` | `package-lock.json`に沿って依存関係を導入 |
| `npm run dev` | Vite画面の開発サーバー（Pages Functionsは提供しない） |
| `npm run build` | 型チェックと本番Webビルド |

現状、専用の自動テストスイートはありません。画面・認証・GAS連携を変更したときは、少なくともビルドとlintに加え、該当する実環境での手動確認を行ってください。

## 3. データモデル

GASは`SPREADSHEET_ID`で指定されたスプレッドシートを開きます。各シートは初回利用時に作成され、1行目がヘッダーになります。既存シートに列の追加・改名を行う場合は、移行手順を決めてからGASとコードを同時に変更してください。

### `Users`

| 列 | 意味 |
|---|---|
| `userId` | UUID形式のアカウントID |
| `email` | 小文字・前後空白除去済みメールアドレス |
| `displayName` | 表示名 |
| `passwordSalt` | パスワード用ランダムsalt（Base64URL） |
| `passwordHash` | PBKDF2-HMAC-SHA256のハッシュ（Base64URL） |
| `createdAt` | 登録日時 |
| `lastLoginAt` | 最終ログイン日時 |
| `failedAttempts` | 連続ログイン失敗数 |
| `lockedUntil` | ロック期限 |

パスワードはPages Functionsで600,000反復のPBKDF2-HMAC-SHA256により処理し、平文では保存しません。5回の失敗で15分間ロックします。

### `Points`

列順は`userSub`, `id`, `latitude`, `longitude`, `accuracy`, `recordedAt`。`userSub`はアカウントUUID、`id`は地点UUIDです。地点IDが既存なら重複登録しない設計です。

### `Spots`

列順は`userSub`, `id`, `title`, `note`, `latitude`, `longitude`, `createdAt`, `driveFiles`。`driveFiles`はDriveファイル参照情報のJSON文字列です。ファイル本体はシートに保存しません。

## 4. APIの役割

| メソッド・パス | 呼び出し元 | 内容 |
|---|---|---|
| `GET /api/auth` | Web画面 | Cookieのログイン状態を返す |
| `POST /api/auth` | Web画面 | `{action:"register", name, email, password}`、`{action:"login", email, password}`、または`{action:"logout"}` |
| `POST /api/sync` | Web画面 | `{data:{points:[], memories:[]}}`をCookie認証後にGASへ中継 |
| `GET /api/oauth/start?state=...` | Capacitor | Google OAuth認可画面へリダイレクト |
| `GET /api/oauth/callback` | Google OAuth | 認可コードを交換してアプリのカスタムURLへ戻す |
| GAS `doPost` | Pages Functions | サービスキー付きのアカウント操作・同期要求を処理 |

認証セッションは7日間のHMAC-SHA256署名Cookieです。Cookieは`HttpOnly`, `Secure`, `SameSite=Lax`で、ブラウザーJavaScriptから直接読み出せません。PagesとGASの`APP_SESSION_SECRET`は同一でなければなりません。

## 5. 必要な環境設定

### Cloudflare Pages

PagesプロジェクトのSettings → Variables and Secretsに設定します。ProductionとPreviewで別の値を使う場合は、各環境に対応したGASデプロイ・シートを用意してください。Previewを本番ユーザーのシートにつなぐと、テストデータが本番DBに入ります。

| 名前 | 種別 | 用途 |
|---|---|---|
| `GAS_EXEC_URL` | Variable | デプロイしたGAS WebアプリのHTTPS `/exec` URL |
| `GAS_SERVICE_KEY` | Secret | PagesとGASだけが共有するランダムなサービスキー |
| `APP_SESSION_SECRET` | Secret | セッションHMAC秘密値。GASのScript Propertiesにも同じ値を設定 |
| `VITE_GOOGLE_CLIENT_ID` | Build variable | WebブラウザーからGoogle Drive APIを利用するOAuthクライアントID。秘密ではない |
| `GOOGLE_CLIENT_ID` | Variable | CapacitorのOAuth開始API用。通常はDrive用と同じOAuthクライアントID |
| `GOOGLE_CLIENT_SECRET` | Secret | CapacitorのOAuthコード交換用 |
| `GOOGLE_REDIRECT_URI` | Variable | `https://<Pagesドメイン>/api/oauth/callback`。Capacitor OAuth利用時のみ |
| `VITE_API_BASE_URL` | Build variable | Capacitorアプリから呼ぶPagesのHTTPS URL。ネイティブ版をビルドする場合のみ |

ブラウザー用の`VITE_GOOGLE_CLIENT_ID`はViteビルド時にWeb資産へ含まれる公開識別子です。OAuthクライアントシークレット、`GAS_SERVICE_KEY`、`APP_SESSION_SECRET`はクライアント側変数（`VITE_`で始まる変数）にしてはいけません。

### Google Apps Script

Apps Scriptプロジェクトの「プロジェクトの設定」→「スクリプト プロパティ」に次を設定します。

| 名前 | 値 |
|---|---|
| `SPREADSHEET_ID` | 使用するスプレッドシートURLの `/d/` と `/edit` の間のID |
| `GAS_SERVICE_KEY` | Cloudflare Pagesの`GAS_SERVICE_KEY`と同じランダム値 |
| `APP_SESSION_SECRET` | Cloudflare Pagesの`APP_SESSION_SECRET`と同じランダム値 |

サービスキーとセッション秘密値は**別々のランダム値**にしてください。新しく生成する場合は、開発端末でNode.jsの暗号乱数を利用できます。

```powershell
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

生成値をターミナル履歴、チャット、GitHubへ貼り付けないでください。安全なパスワード管理手段を使ってCloudflareとGASへ個別に登録します。

### GAS Webアプリの公開

1. `gas/Code.gs`をApps Scriptプロジェクトに反映します。
2. 上記Script Propertiesを設定します。
3. 「デプロイ」→「新しいデプロイ」→「ウェブアプリ」を選びます。
4. 実行ユーザーをスクリプト所有者、アクセスできるユーザーを「全員」に設定します。Cloudflareから実行するためGoogleログイン不要のURLが必要ですが、処理は`GAS_SERVICE_KEY`とセッション署名を検証します。
5. 表示された `/exec` URLをCloudflareの`GAS_EXEC_URL`に設定します。
6. `Code.gs`を変更した後は、既存デプロイを新しいバージョンに更新してください。エディターに保存しただけでは公開中Webアプリへ反映されません。

スプレッドシートの共有権限は必要最小限に制限してください。GAS WebアプリURLが公開されるため、サービスキーを漏えい・Git管理しないことが重要です。

### Google Drive OAuth

1. Google CloudでOAuth同意画面を設定し、Webアプリケーション種別のOAuthクライアントを作成します。
2. Google Drive APIを有効にします。アプリは`drive.file`権限を要求します。
3. JavaScript生成元に `http://localhost:5173` とWebアプリのPagesドメインを登録します。
4. Capacitor用OAuthを使う場合のみ、承認済みリダイレクトURIに`GOOGLE_REDIRECT_URI`を登録します。
5. `VITE_GOOGLE_CLIENT_ID`はWeb画面のビルド時に利用されます。値を変更したらPagesを再ビルド・再デプロイしてください。

メールアドレスとパスワードによるアプリログインはGoogle OAuthとは別です。Drive OAuthは写真・動画ファイルの保存許可に使います。

## 6. ローカルで全機能を動かす

Node.jsとnpmを用意し、次を実行します。

```powershell
npm install
Copy-Item .env.example .env.local
Copy-Item .dev.vars.example .dev.vars
```

`.env.local`の`VITE_GOOGLE_CLIENT_ID`を設定します。`.dev.vars`にはローカル用Pages環境変数を設定し、GAS Script Propertiesと共有する値はGAS側と一致させます。`.env.local`と`.dev.vars`はGitへ追加しないでください。

画面だけなら`npm run dev`で確認できます。ただし、Vite開発サーバーは`functions/`のAPIを実行しないため、メール認証・同期は動きません。APIも含める場合はPages開発サーバーを利用します。

```powershell
npm run build
npx wrangler pages dev dist
```

利用中のPages Functions APIの変更をローカルで検証するには、同一のCloudflareバインディングと秘密値を`.dev.vars`に設定してください。Google OAuthの公開URL・redirect URIは、localhostで利用する場合もGoogle Cloud側へ登録してください。

## 7. GitHubからCloudflare Pagesへ公開

1. 変更をGitHubのこのリポジトリへpushします。
2. Cloudflare PagesでGitHubリポジトリを接続します。
3. Build commandを`npm run build`、Build output directoryを`dist`にします（`wrangler.toml`も`dist`を指定しています）。
4. 「5. 必要な環境設定」をPagesのProduction（必要ならPreview）へ設定します。
5. Buildを実行し、デプロイログを確認して公開URLで登録・ログイン・GPS・スポット・同期をテストします。

アプリは**GitHub PagesではなくCloudflare Pages**で公開します。GitHubはソース管理とPagesへのデプロイ連携に使います。

## 8. データの流れと運用上の注意

- GPS地点・スポットはブラウザーのIndexedDBに保存され、ユーザーが同期を実行するとGAS経由でスプレッドシートに反映されます。
- 写真・動画本体はGoogle Driveへ直接アップロードし、ファイル参照情報をアプリデータとして同期します。
- Service Workerはアプリシェルや静的ファイルをキャッシュします。`/api/`はキャッシュしません。
- ログアウトはCookieと端末上の選択中アカウントを解除します。ユーザー行や同期済みデータの削除は行いません。
- Web版GPSはページを開いている間のみ利用可能です。画面ロック・タブ切替・ブラウザー終了時の記録継続を保証しません。
- GAS/Cloudflare障害時は登録、認証、同期が失敗します。ブラウザー側に同期前データがある場合は、サイトデータを削除せず復旧後に同期してください。

公開前に位置情報・メールアドレス等の取扱い、スプレッドシートのアクセス権、バックアップ、アカウント対応手順を運営者間で確認してください。現状はメール確認、パスワード再設定、アカウント削除、IP単位のレート制限が未実装です。

## 9. 変更時の確認

1. 画面・データ型を変更する場合は`src/`、APIの入出力を変更する場合は`functions/api/`と`gas/Code.gs`を合わせて更新します。
2. `npm run build`と`npm run lint`を実行します。
3. GASの列構成を変えた場合は既存シートの移行を確認し、Apps ScriptのWebアプリを再デプロイします。
4. ローカルPages環境またはテスト用Pages/GAS/シートで、登録・ログイン・同期・ログアウトを確認します。
5. Drive変更はOAuth許可スコープ、Google Cloud設定、プライバシー説明を確認します。
6. GitHubへpushし、Cloudflareのデプロイ結果とProductionの動作を確認します。

AndroidはAndroid StudioとAndroid SDK、iOSはmacOSとXcodeが必要です。Web版の認証方式とネイティブ版のOAuth連携は同一機能ではないため、ネイティブ版へメールアカウント認証を展開する場合は認証セッションの受け渡しを別途設計・検証してください。
